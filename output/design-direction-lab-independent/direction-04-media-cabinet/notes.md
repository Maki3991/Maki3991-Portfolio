# 04 · Media Cabinet / 媒体档案柜

## 视觉核心假设

如果 Maki 的核心证据首先来自内容作品，首页可以像一个媒体档案柜：先让真实封面和作品入口成立，再让项目、Note、About、Now、Contact 以少量大块内容接上来。这里不是把所有东西卡片化，而是有意识地测试“作品先行”的语言。

## 结构与排印

- 构图：首屏是左侧定位块 + 右侧真实作品面板；下方是一个大项目块、一个作品块和一个 Note 块的媒体柜。
- 字体：超粗无衬线标题、等宽标签、黑灰底和冷青 / 粉色两处受控信号色。
- 信息密度：低到中。先看封面、标题和少量关键数据，完整职责与长期内容仍由后续 detail/index 承担。
- 项目 / 文章：项目是大块主档案，作品是证据块，Note 是短文本柜格；不假装已有完整文章库。
- 导航：顶部轻导航；移动端原生菜单，页面本身依靠清楚的区块标题滚动。
- 图片 / 媒体：V028 真实封面是第一视觉入口和可点击外链；不重复生成装饰图。
- 动效：真实封面只做极轻微 hover scale；所有信息静态可见，支持 reduced-motion。

## 参考来源

- [Jakub Jakubik](https://jakubjakubik.com/)：少量强视觉索引与克制导航。
- [Rome Michal](https://romemichal.pl/)：精选项目先行、详情再承载过程与结果。
- [Andrew Aarestad Mood Board](https://www.andrewaarestad.com/design-preview/v1-initial)：把媒体、按钮、表格等系统单元变成可比较的样例。
- 研究基线中的“首页只放少量精选入口；不要把统计数字单独做成 Dashboard”。

## 适合长期更新的地方

它适合不断替换或追加“柜格”里的作品和项目，每个格子都能链接到以后稳定的 detail/index 模板。真实封面可作为内容记录中的可选 cover，不要求每个未来栏目都做新视觉。

## 可能的问题和风险

视觉存在感较强，容易让访客把网站理解成单纯内容账号档案；如果长期增加文章、经历和方法说明，必须及时把柜格入口接到普通列表与详情页。大图对移动端速度和封面裁切要求更高。
