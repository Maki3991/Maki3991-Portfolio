# Site Content Outline v0.1

状态：提案稿，待 Maki 反馈  
用途：在旧网站审计和正式开发前，先确定网站展示什么、为什么展示、各页面如何分工。

本文件是我的默认方案，不是已经确认的最终信息架构。它不锁定最终文案、颜色、尺寸、组件代码和具体实现。

---

## 1. 核心判断

我建议把网站定义为：

> 一个持续更新的个人工作档案，记录 Maki 做过什么、正在做什么、如何做判断，以及这些工作留下了什么证据。

网站不需要一开始就像：

- 完整简历数据库；
- 新闻博客；
- 社交平台；
- 复杂的个人 Dashboard；
- 把所有生活数据都公开的个人操作系统。

页面分工如下：

| 页面 | 主要回答的问题 | 内容性质 |
| --- | --- | --- |
| Home | Maki 是谁、最近在做什么、有哪些工作值得继续了解？ | 当前切片和入口 |
| Archive | Maki 做过哪些项目、作品、实验和研究？ | 长期总档案 |
| Archive Detail | 某件工作如何发生、Maki 做了什么、结果如何验证？ | 深度证据 |
| Now | Maki 当前把注意力放在哪里，为什么？ | 阶段性状态 |
| About | Maki 的背景、经历、兴趣和工作方式如何形成？ | 长期脉络 |
| Contact | 如果想联系 Maki，应该通过什么方式、讨论什么事情？ | 行动入口 |

因此：

- Home 不是 Archive 的缩小版；
- Now 不是把 Archive 中标记为“进行中”的项目再列一次；
- About 不是把 Home 的自我介绍再扩写一遍；
- Contact 不需要为了完整而堆成很长的页面；
- 长期可更新性主要由 Archive、Now 和详情页承担。

## 2. 第一版范围

### P0：必须成立

- Home；
- Archive；
- 至少一个真实的 Archive Detail；
- Now；
- About，或先作为 Home 的可进入模块；
- Contact，或作为共享入口；
- 共享 Header、Footer、返回路径和移动端基本可用性。

### P1：有真实内容再加入

- Currently Reading；
- Current Questions / Open Loops；
- 最近更新；
- 项目筛选；
- 证据图集；
- 简历下载；
- RSS 或更新订阅；
- 读书、收藏、研究等专门页面。

### 暂不做

- 复杂实时数据；
- 健身或生活仪表盘；
- 多层标签搜索；
- 没有真实内容支撑的 Notes、Blog 或 Collections；
- 纯装饰性的互动实验。

判断标准是：是否有真实素材、是否愿意长期维护、是否能帮助访客准确理解 Maki。

## 3. Home / Working Archive

### 3.1 Home 的任务

Home 只需要让访客在较短时间内得到五个答案：

1. Maki 现在是谁；
2. Maki 正在关注什么；
3. Maki 做过哪些值得展开的工作；
4. 这个网站为什么值得以后再回来；
5. 如果想继续了解或联系，下一步去哪里。

Home 应该像档案馆的入口，而不是把全部档案一次性搬到门厅。

### 3.2 建议的纵向顺序

#### 0. Shared Header

内容：

- Maki / 羽轩的身份标识；
- Home；
- Archive；
- Now；
- About；
- Contact 或明确的联系入口；
- Light / Dark mode；
- 当前路径或简洁的状态提示。

验收：

- 访客始终知道自己在哪里；
- 主要页面容易到达；
- Header 不抢过页面内容本身。

#### 1. Hero / Identity

建议内容：

- Maki / 羽轩；
- 当前的一句话身份；
- 一段很短的真实介绍；
- 一个主行动：进入 Archive 或查看代表工作；
- 一个次行动：联系 Maki；
- 可选头像或个人照片。

当前可以使用的事实基础：

- 英语内容创作者；
- 内容运营实践者；
- 国际政治本科生；
- 关注英语学习、内容表达、自媒体运营、教育产品和 AI 辅助创作；
- 正在把内容、项目和学习系统整理成长期可验证的作品集。

这里需要的是可记住的定位，不是完整自传。

#### 2. Live Index / Current Facts

用简短事实代替夸大的数据卡片：

- CURRENTLY：当前身份或阶段；
- FOCUS：当前投入的方向；
- BASED：所在地区；
- OPEN TO：寻找的机会或合作；
- UPDATED：最近更新时间。

数字必须有来源和时间范围。不要为了让首页看起来有数据而添加无法解释的指标。

#### 3. Current Workbench / 当前工作台

这是我建议第一版重点尝试的模块。

每项包含：

- 当前事项；
- 类型：项目、内容、学习、系统或其他；
- 状态：进行中、维护中、暂停、下一步；
- 为什么现在做；
- 下一步；
- 相关 Archive 或 Now 链接。

只放 2–4 项，不要变成任务清单。Home 提供摘要，Now 再解释背景、取舍和暂时不做什么。

#### 4. Selected Work / 代表性工作

建议选择少量能够代表不同能力的条目：

- 内容或运营类；
- 教育产品或交付类；
- AI 辅助开发或系统类；
- 必要时再加一个正在进行的工作。

每项只展示：

- 标题；
- 类型；
- 状态；
- 一句话说明；
- Maki 的角色；
- 一条可验证事实；
- 详情链接。

当前候选：

- Maki English 自媒体；
- 英语教育产品与社群交付；
- Audibooker；
- 新个人网站重建和知识系统项目。

选择逻辑应该是：这些条目合起来能否看出 Maki 的能力组合和思考方式，而不是单纯选择看起来最厉害的项目。

#### 5. Archive Entry / 档案入口

用很短的说明告诉访客：

- 这里不只是展示完成品；
- Archive 会逐步收录项目、作品、实验和研究；
- 部分条目会记录过程、取舍、证据和下一步。

不要把这一段写成抽象宣言。

#### 6. Optional：Currently Reading 或 Current Question

第一版最多选择其中一个。

Currently Reading 只有在每本书有“为什么现在读、和什么问题有关”的判断时才值得出现。

Current Question / Open Loop 可以展示 1–3 个正在思考、验证或尚未解决的问题。这更符合长期工作档案，也不要求 Maki 先成为稳定的文章作者。

我的默认偏好是：如果还没有稳定的读书记录，优先尝试 Current Question / Open Loop。

#### 7. Short About / How I Work

首页末尾可以放一小段背景和工作方式，链接到 About。不要写“热爱创造、持续成长、追求卓越”这类不能被项目证明的话。

#### 8. Contact / Next Step

说明：

- 什么事情适合联系 Maki；
- 首选联系渠道；
- GitHub 和内容平台链接；
- 微信二维码对应什么渠道；
- 进入 Contact 或直接发邮件的行动。

#### 9. Footer

当前年份、更新状态、主要外部链接、主题切换和必要的版权信息。

### 3.3 Home 的最小版本

如果内容不足，先保留：

1. Hero；
2. Live Index；
3. Current Workbench；
4. Selected Work；
5. Contact / Footer。

Reading、Current Question 和 Short About 都由真实内容驱动，不为凑完整而强行加入。

## 4. Archive：长期积累的主页面

### 4.1 Archive 的任务

Archive 应允许 Maki：

- 新增一个项目；
- 新增一个实验；
- 新增一项研究；
- 新增一件作品；
- 修改状态和更新时间；
- 不必重新设计整套页面。

### 4.2 统一条目字段

每个条目建议至少有：

- title：标题；
- type：类型；
- status：状态；
- date 或 updated：发生时间 / 最近更新；
- summary：一句话摘要；
- role：Maki 在其中做了什么；
- evidence：有什么可以验证；
- next：下一步或当前未完成事项；
- detail link：是否有完整详情；
- related：相关条目。

类型先控制在：

- PROJECT：项目；
- WORK：内容或作品；
- EXPERIMENT：实验；
- RESEARCH：研究或学习系统；
- SYSTEM：正在维护的长期系统。

不要一开始就把类型拆得太细。分类的目的是帮助理解，不是建立复杂数据库。

### 4.3 列表顺序

第一版可以按：

1. 当前进行中的条目；
2. 最近更新的条目；
3. 代表性已完成条目；
4. 其他历史条目。

如果数量很少，不需要立即上筛选器。先保证列表能读、状态真实、每个条目有下一步或结果。

### 4.4 Projects 和 Works 是否合并

我的默认建议是合并。

理由：

- 旧网站中 Projects 和 Works 已经存在内容重叠；
- Maki 的实际工作常常同时包含内容、运营、产品和系统；
- 访客更想知道做过什么以及承担了什么，不一定需要先理解旧分类；
- 统一 Archive 更适合增加实验、研究和长期系统。

可以保留 type 标签，让访客知道条目属于项目、作品还是研究。

## 5. Archive Detail：让证据具体落地

详情页不是一张更大的项目卡，而是让访客理解这件工作如何发生。

建议顺序：

1. 标题、类型、状态、更新时间；
2. 一句话说明；
3. Context：背景和为什么开始；
4. Problem：要解决的具体问题；
5. Role：Maki 负责和判断了什么；
6. Process：经历过哪些重要阶段；
7. Decisions：做过哪些关键选择；
8. AI Boundary：AI 参与了什么，Maki 如何判断和验收；
9. Deliverables：最终留下了什么；
10. Evidence：哪些材料证明结果或过程；
11. Result：目前产生了什么结果；
12. Unresolved：还有什么没有解决；
13. Next：下一步；
14. Related：相关项目、Now 或其他档案。

Evidence 不等于图片堆。证据可以是：

- 项目在线链接；
- 代码仓库；
- 发布页面；
- 产品截图；
- 前后版本截图；
- 平台数据截图；
- 用户反馈或交付记录；
- 过程中的决策记录；
- 测试结果；
- 明确的时间、范围和角色说明。

每份证据最好附一句说明：这是什么、证明什么、时间范围是什么、有什么局限。

当前项目的可用素材：

- Maki English：已有播放、互动和单条峰值等数据，但还需要时间范围、平台范围和截图说明；
- 英语教育产品与社群交付：已有职责和交付节奏，可以继续补充公开直播主题、服务记录或反馈；
- Audibooker：已有产品功能、技术和部署信息，可以补充封面截图、使用流程和数据来源；
- 新个人网站：可以记录需求判断、组件选择、参考网站、AI 协作和验收过程，但不要写成工具流水账。

## 6. Now：不是进行中的项目列表

Now 应回答：

> Maki 目前处于什么阶段，注意力为什么放在这里，接下来准备推进什么，同时暂时不做什么？

建议结构：

1. Last updated；
2. Current phase：当前阶段；
3. 2–4 个当前重点；
4. Why now：为什么现在做；
5. What I am not doing：暂时不做什么；
6. Current questions：仍在思考或验证的问题；
7. Open to：欢迎怎样的交流或合作；
8. Related links：相关项目和档案。

更新方式可以是阶段发生变化时，或每月、每季度一次，不需要每天更新。

边界：

- Archive 记录做过和正在维护的东西；
- Now 记录此刻的注意力和取舍；
- Archive 条目可以长期存在；
- Now 内容可以替换、过期和重写；
- Now 也可以包含读书、学习、求职、方向判断等不属于项目的内容。

## 7. About：解释长期脉络

About 应回答：

- Maki 的背景如何形成；
- 为什么同时关注内容、教育、AI 和系统；
- 过去经历之间有什么连续性；
- Maki 如何工作和做判断；
- 未来愿意往什么方向继续发展。

建议内容：

1. 一段真实的背景介绍；
2. 当前阶段；
3. 经历和能力的形成过程；
4. 长期关注的问题；
5. 工作方式；
6. 正在寻找的机会；
7. 相关档案和联系方式。

工作方式尽量用事实写，例如如何从问题开始、如何用 AI 辅助研究和实现、如何自己做选择和验收、如何保留结果和未完成事项。

如果目前只有简历式介绍，About 可以先作为 Home 的入口模块，等材料成熟后再独立成页。

## 8. Contact：以真实联系为目标

第一版内容：

- 首选邮箱；
- GitHub；
- 微信二维码，如果确实用于联系；
- 抖音、小红书、视频号等内容平台；
- 什么类型的机会适合联系 Maki；
- 可选的简历 PDF。

需要避免：

- 把所有账号平铺成同等重要；
- 只显示图标，不说明用途；
- 只写欢迎交流但没有联系路径；
- 保留不再维护的账号；
- 把公开联系和私人生活混在一起。

第一版可以保留独立 Contact 路由，也可以让它作为 Home、About、Now 和 Footer 的共同入口。最终取决于联系方式的数量和内容是否足够。

---

## 9. Currently Reading：现在要不要加入

建议加入“可扩展的内容类型”，但不一定马上做独立页面。

作为 Home 或 Now 的小模块时，每本书最好有：

- 书名和作者；
- 当前读到哪里；
- 为什么现在读；
- 和当前项目、职业方向或问题有什么关系；
- 一句真实的暂时结论。

如果只是封面和书名列表，它和普通书单没有明显区别。

积累足够后，再考虑独立阅读页面、按主题整理、阅读时间线和书与项目的关联。

## 10. 旧网站内容迁移建议

| 旧网站内容 | 新结构的默认去向 | 处理建议 |
| --- | --- | --- |
| 旧 Home Hero | Home Hero | 保留真实身份，重新压缩和重排 |
| 旧 Home 数据卡片 | Home Live Index 或详情 Evidence | 核对来源和时间范围 |
| 旧 Home 三件事 | Home Workbench 或 Archive | 不直接照搬卡片标题 |
| 旧 Home 精选作品 | Home Selected Work | 重新定义代表性选择逻辑 |
| Projects 页面 | Archive | 与作品、实验、研究统一 |
| 项目详情 | Archive Detail | 分层记录职责、过程、证据、下一步 |
| Works 分类 | Archive 的 type 字段 | 只有有助于理解时才保留 |
| Works 证明材料 | Archive Detail Evidence | 说明每份材料证明什么 |
| About 页面 | About | 去掉泛泛的价值宣言 |
| Contact 页面 | Contact、Footer 和相关入口 | 保留真实渠道，减少重复入口 |
| reflection 字段 | Decisions、Result、Unresolved | 改成具体经历 |
| next 字段 | Now、Detail 的 Next | 根据当前状态核对是否仍有效 |

迁移原则：

1. 旧代码只是待审计的实现，不是新网站的视觉和内容权威；
2. 旧文案可以作为素材，但不能默认照搬；
3. 旧分类可以合并；
4. 旧数据只有在可解释、可验证时才进入新版；
5. 新结构先由内容职责决定，再决定组件和代码。

## 11. 我认为方案中比较平庸的地方

以下部分能工作，但本身不构成独特性：

### 11.1 Hero

名字、身份、一句话介绍是标准个人网站结构。它的作用是清楚，不是独特。

需要 Maki 决定：

- 不希望被记成什么；
- 内容、运营、国际政治、教育和 AI 之间最重要的连接是什么；
- 是否存在更像自己的表达；
- 访客看完 Hero 后应该产生什么继续浏览的理由。

### 11.2 Live Index

Role、Location、Seeking、Focus 很实用，但仍像标准个人档案。只有事实足够具体时才有价值。

### 11.3 Selected Work

精选项目卡片很常见。它需要属于 Maki 的选择逻辑，而不是单纯选择三个看起来最厉害的项目。

### 11.4 About

背景、兴趣、工作方式和发展方向是标准内容。独特性来自真实经历的顺序、转折和判断，不来自栏目名称。

### 11.5 Contact

联系方式的价值是清楚、可信和容易使用，不需要强行做成一件视觉作品。

### 11.6 Currently Reading

书单很容易变成装饰。必须有“为什么读、改变了什么、和现在做的事情有什么关系”。

### 11.7 How I Work

“我重视问题、迭代、反馈和长期积累”几乎所有人都可以说。更可信的是放回具体项目中，记录选择、否定、验收和未解决问题。

## 12. 值得 Maki 补充的独特方向

这些不是必须加入的功能，而是可能让网站变成只有 Maki 才会这样组织的档案。

### 12.1 Current Questions

记录正在试图理解、验证或尚未解决的问题。它适合长期更新，也不要求 Maki 先成为稳定的文章作者。

### 12.2 Open Loops

保留未完成部分、当前阻塞点、下一次尝试、被放弃的假设和暂时不能下的结论。它比“持续成长”更具体，但需要接受公开不完整状态。

### 12.3 Evidence Shelf

把证据和判断绑定：证据是什么、证明哪个结论、不证明什么、来自什么时候、Maki 如何解释。

### 12.4 AI Collaboration Ledger

在重要项目中记录 AI 做了哪些研究、生成、实现和整理；Maki 做了哪些方向选择；哪些方案被否定；如何验收；哪些结果仍然不确定。

重点不是展示会用 AI，而是展示 Maki 如何保持判断权和责任边界。

### 12.5 Content → Delivery → System

已有经历可能形成一条连续线索：

- 内容创作：表达、选题和受众；
- 教育交付：服务、反馈和持续运营；
- 产品与系统：把经验固化成可使用的工具和档案。

这条线索只有在符合 Maki 对自己的理解时才采用，不能由网站替 Maki 宣布。

### 12.6 我不做什么

在 Now 或 About 中说明当前暂时不追求什么、哪类项目不再投入、为什么放弃某个方向，以及这次取舍释放了什么注意力。

## 15. 对旧网站审计的影响

旧网站审计不应该直接从哪个页面代码写得好不好开始。每个旧页面和内容块都要回答：

1. 它在新结构中属于哪个页面；
2. 它服务于哪个访客问题；
3. 它是事实、判断、装饰还是历史遗留；
4. 它是否有真实内容和证据；
5. 它应该保留、重写、合并、降级还是删除；
6. 它是否会把新版带回旧的 AI 味或模板化表达；
7. 它是否值得保留一个长期维护入口。

建议的审计顺序：

1. 旧 Home：内容块和叙事顺序；
2. 旧 Projects / Works：合并为 Archive 的可行性；
3. 一个项目的 Detail 深审；
4. 旧 About：是否有真实个人叙事；
5. 旧 Contact：独立页还是共享入口；
6. 根据审计结果更新 Site Content Outline v0.2。
