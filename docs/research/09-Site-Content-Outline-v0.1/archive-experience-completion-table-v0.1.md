# Archive 五个项目经历补充表 v 0.1

## 使用方式

这份表用于补充 Archive 的事实材料，不要求现在就写成最终文案。

- 能公开的内容直接填写。
- 不能公开的内容填写“不可公开”或“可匿名化”。
- 暂时没有数据的内容填写“暂无可量化数据”，不要为了完整而编造数字。
- 先补充事实，再由我整理成 Archive 列表页、详情页和 Home 精选项目需要的文案。

当前目标：4 个已有 Archive 项目 + 1 个音乐项目，共 5 个项目经历。

## 一、所有项目统一需要补充的字段

| 字段       | 需要补充什么                     | 你的填写提示                      |
| -------- | -------------------------- | --------------------------- |
| 项目名称     | 对外显示的正式名称                  | 如果需要匿名，提供一个可公开的替代名称         |
| 项目类型     | 这个项目属于什么类型                 | 例如：独立项目、实习项目、内容项目、活动项目、音乐项目 |
| 时间       | 开始时间、结束时间或持续至今             | 不确定具体月份时，可以先写年份或时间段         |
| 当前状态     | 进行中、已完成、暂停、已归档等            | 说明现在是否还在维护                  |
| 一句话概述    | 项目做什么、服务谁、解决什么问题           | 先写事实，不必追求宣传感                |
| 你的角色     | 你在项目中的身份和责任范围              | 区分“参与了”与“负责了什么”             |
| 具体贡献     | 你实际做过的 3—5 件事情             | 用动作描述：设计、运营、写作、开发、组织、交付等    |
| 产出物      | 项目实际留下了什么                  | 例如：账号、文章、产品、活动、歌曲、专辑、系统、报告  |
| 结果       | 项目产生了什么可观察结果               | 可以是数据，也可以是明确的非量化结果          |
| 证据与链接    | 可以证明项目存在或成果的材料             | 网站、文章、作品链接、截图、公开页面、文件等      |
| 合作关系     | 是否有团队、客户、合作者或组织            | 写清你的边界，不必列出不能公开的姓名          |
| 公开边界     | 哪些信息可以公开，哪些需要隐藏或匿名化        | 尤其注意公司、客户、内部数据、联系方式和版权材料    |
| 限制与未完成部分 | 项目有什么限制、哪些目标没有完成           | 这会让经历更可信，不是负面信息             |
| 关联内容     | 是否有 Works、文章、Now 或其他页面可以关联 | 没有就写“暂无”                    |
