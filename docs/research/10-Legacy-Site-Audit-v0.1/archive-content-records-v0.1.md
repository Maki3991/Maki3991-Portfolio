## 1. 记录规则

本文件只记录已经有来源的内容，并明确哪些信息还不能公开或不能夸大。

事实优先级：

1. Maki 在当前决策摘要中的最新填写；
2. 本地记忆库中已经归档的正式项目记录；
3. 旧版网站内容；
4. 仍需核对的简历、截图、仓库和外部链接；
5. Agent 推断不得直接变成公开事实。

公开状态：

- public：可以进入公开 Archive；
- public-anonymized：可以公开，但隐藏公司、合作方、用户或内部数据；
- evidence-pending：可以作为条目整理，但证据还没有准备好；
- private：不进入当前公开页面。

### 可公开结果

- 完成可展示的黑客松 MVP；
- 有公开 GitHub 仓库；
- 有 AdventureX Gallery 页面；
- 有 ReadAge Demo；
- 有 Flyer 和展示视频；
- 没有获得奖项；
- 没有可靠的赛后持续使用或用户反馈数据。

### 证据边界

- GitHub 仓库包含赛后 8 月的继续开发，不能把所有后续功能写成 7 月现场版本；
- 现场最终功能清单仍需以活动版本、截图或具体 commit 核对；
- Flyer 的设计和本地 PDF 可以作为个人设计产出；
- 不能把完成 Demo 写成产品已经被验证成功。

### 对外可以表达的重点

这个条目的重点不是“获奖”或“产品增长”，而是：

- 在时间有限、两人协作的情况下完成一个可展示 MVP；
- 负责 Landing Page、CEFR 测试、本地数据和展示物料；
- 通过这次经历开始形成 GitHub 协作和 AI 辅助构建的实际经验；
- 能诚实区分现场版本、赛后迭代和未经验证的产品假设。
