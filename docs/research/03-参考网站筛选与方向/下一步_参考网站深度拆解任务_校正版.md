Maki 已明确两个关键约束：

1. 网站要成为可以持续多年更新的个人空间，不是一次性作品集。
2. 不希望第一版依赖复杂动效；动效可以有，但必须可控、可删除、不能破坏阅读和维护。

## 本轮唯一目标

把这些参考网站拆成三种东西：

1. **长期内容骨架**：以后增加项目、文章、经历、Now 或新栏目时，如何只增加内容而不重做 UI。
2. **视觉设计基线**：颜色、字体、版式、密度、边界、导航、卡片、图片和信息层级的可观察规则。
3. **动效边界**：哪些动效有信息价值，哪些只是装饰，哪些实现/维护风险过高。

不要试图找出一个“全都照搬”的网站。每个参考只承担它确实擅长的角色。

## 对每个选中网站的检查范围

优先检查公开可访问的：

- 首页；
- 一个作品/项目索引页；
- 一个项目详情页、文章页或经历页；
- 导航打开/关闭、主题切换、筛选、目录、返回顶部等可见状态；
- 移动端宽度下的结构；
- 键盘焦点和 `prefers-reduced-motion`，如果页面有对应行为。

每个判断都要标注证据类型：

- `用户观察`：Maki 在 `docs/web-list.md` 中明确说过的喜欢或不喜欢；
- `页面事实`：实际页面上看到的栏目、链接、状态或内容；
- `来源自述`：网站作者在页面或案例中对方法的描述；
- `本项目推断`：结合 Maki 的目标得出的适用性结论；
- `未核验`：无法从当前公开页面确认的内容。

## 必须产出的文档

### 1. 参考网站证据矩阵

每个网站至少记录：

| 字段 | 要回答的问题 |
| --- | --- |
| 角色 | 它是内容骨架、职业表达、视觉语言、动效，还是设计方法参考？ |
| 长期更新 | 新增项目/文章/栏目需要改什么？ |
| 页面模式 | 它是否有首页、索引、详情、归档等可复用模式？ |
| 内容密度 | 适合短内容、长文、项目案例还是经历信息？ |
| 动效 | 动效做了什么；删掉后功能是否仍完整？ |
| 适用部分 | Maki 可以借鉴什么？ |
| 排除部分 | 哪些部分不应作为第一版基础？ |
| 证据 | 页面链接、截图路径、观察记录或作者原文链接 |

### 2. Maki 的 Design Baseline v0.1

不能只写“极简、高级、现代”这类形容词，至少要形成可检查的规则：

- 色彩角色：背景、表面、主文字、次文字、强调色、边框、焦点态；必须预留亮色/暗色主题的 token 位置；
- 字体角色：标题、正文、标签、代码和中英文混排的职责；
- 布局：内容最大宽度、边距、网格、阅读宽度和页面密度；
- 视觉边界：圆角、阴影、线条、分隔、卡片使用边界；
- 导航：全局导航、移动端导航、文章目录、回到顶部和搜索的优先级；
- 内容呈现：项目卡片、项目详情、文章/笔记、经历、Now/近期状态的页面模式；
- 文案：避免空泛自我介绍和机械 AI 句式；
- 明确排除：暖色衬线模板感、常见橙绿淡黄组合、无意义卡片堆叠、装饰性过度动效。

### 3. 长期扩展验收规则

提出至少三个模拟操作：

1. 新增一个项目；
2. 新增一篇文章或笔记；
3. 新增一个未来栏目。

验收标准：主要修改内容文件、元数据或栏目配置，不修改已有组件的视觉代码；如果做不到，要明确记录阻塞点。

### 4. 动效策略表

将动效分成：

- 默认允许：hover、淡入、轻微位移、菜单展开、主题切换；
- 需验证：滚动触发、阅读进度、局部视差、页面转场；
- 第一版不作为核心：滚动劫持、复杂 Canvas/WebGL、依赖大量时间轴的全屏动画。

每一个保留动效都要说明：触发条件、用户收益、移动端行为、关闭方式、`prefers-reduced-motion` 行为和删除后的降级结果。

## 完成条件

本轮完成，不等于“网站重建完成”。只有同时满足以下条件，才算完成 Design Baseline 阶段：

- 选中网站已经按角色分类，不再把视觉样本当成技术底座；
- 每条核心规则都有页面证据、用户反馈或明确推断来源；
- 能说清楚新增内容和新增栏目的维护路径；
- 能说清楚第一版动效的边界和降级方式；
- 形成首页、项目详情、文章/笔记索引三个页面的结构草图；
- Maki 能对规则做“保留 / 修改 / 排除”判断。

## 下一道闸门

Maki 审核 Design Baseline v0.1 后，才进入 `lab / laboratory`：为首页首屏、项目详情和文章索引制作 3–5 个可预览方向。方向确认前，不开始全站重构，不引入完整模板，也不把复杂动效直接写进公共组件。

这一步对应直播摘要中的“先用局部页面打样，再逐个板块落地”，并把 Maki 的长期维护目标提前纳入验收。
