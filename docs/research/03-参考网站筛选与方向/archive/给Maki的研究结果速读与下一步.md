# 给 Maki 的研究结果速读与下一步

> 这是给网站所有者看的短版，不是给新 Agent 的完整背景文档。
>
> 更新：2026-09-14

## 你现在不需要做什么

你不需要通读逐字稿、主研究报告、候选表和证据账本。它们是给 Agent 查证和继续工作的资料库。你现在只需要看这份速读，然后亲自打开少量真实页面做选择。

## 这轮研究已经回答了什么

1. 这个网站应当是长期存在、持续更新的个人空间，不是一次性简历页。
2. 不能依赖某个现成模板解决问题；应该建立自己的内容模型、设计 Token、组件边界和验收方式。
3. 技术上可以继续沿用静态 Astro，但参考模板不能直接视为可用底座。SDBurt 和 Astro Kami 的隔离构建成功，hmbldv 的示例仓库构建失败，详细结果见构建记录。
4. 第一版栏目现在不必全部决定。先让新增栏目能够复用同一套页面骨架、内容 schema 和视觉规则。

## 按直播流程，下一步是什么

现在进入第二个 gate：**真实页面选择方向**。

直播里的顺序是：宽范围研究 → 从候选中筛选 → 人通过真实页面判断喜欢什么 → AI 制作可视化方向实验 → 人选择和融合 → 只落地一个局部页面。

因此下一步不是继续搜更多网站，也不是重构现有网站，而是请你浏览下面这组少量候选：

| 页面 | 你重点观察什么 | 不需要照搬什么 |
|---|---|---|
| [SDBurt](https://sdburt.com/) | 首页、项目索引、项目详情如何共同承载长期内容 | Astro 版本和部署配置 |
| [Astro Kami](https://automann.github.io/astro-kami/) | 文章、标签、Showcase、详情页和中文内容结构 | 编辑型衬线字体和默认配色 |
| [Kepler Work](https://astro-kepler.pages.dev/work/) | 项目筛选、年份、类型和 case study 的关系 | navy/orange、硬阴影和营销页气质 |
| [bueno.fyi](https://bueno.fyi/) | 目录、分类、搜索、长列表和个人互联网入口 | 纯目录对项目叙事的限制 |
| [Robert Feasley](https://rfeasley.io/) | 作品、背景、影响和 CV 如何组织在一起 | 尚未核验的细节页模式 |
| [Specia1ne](https://specia1ne.com/) | 编号、连续结构轴、滚动和局部交互 | 一页式结构对长期新增内容的限制 |

hmbldv 暂时只作为项目版本、提交记录、Wiki 和文档式详情页的信息模型参考，不作为需要你浏览的视觉样例。

## 你只需要给出什么反馈

不用使用设计术语。对每个页面写四句话即可：

```text
我喜欢：
我不喜欢：
我想借用：
我还没看懂/想继续观察：
```

最重要的不是给网站打分，而是指出具体的可见选择：页面密度、信息顺序、导航方式、项目展示、文章阅读感、颜色气质、字体性格、边界/圆角、动效是否干扰阅读。

## 你反馈之后，Agent 才做什么

默认先以首页首屏和一个项目详情页作为实验对象，制作 3–5 个低保真方向，而不是直接重写全站。每个方向会写清：

- 页面骨架；
- 内容 schema；
- Token 和组件集合；
- 视觉语言；
- 动效边界；
- 以后新增栏目如何接入；
- 维护和技术风险。

你选择或融合其中的方向后，才沉淀成第一版 Design Baseline，再落地一个真实页面链路。页面通过局部验收后，才扩展到其他栏目。

## 目前的默认假设

- 第一批实验对象：首页首屏 + 项目详情页。
- 第一批实验目的：确认“这个网站像不像 Maki”，不是确认全部栏目。
- 颜色、字体和动效目前都不定稿。
- 未来新增栏目优先通过内容集合和页面模式接入，不要求你重新设计 UI。

如果你不想逐个写反馈，也可以只回复每个页面的“保留 / 排除 / 想融合”三项；Agent 会把它们整理成实验室输入。
