# Site Map v0.1

状态：`PROVISIONAL`

更新时间：2026-09-14

## 1. 当前定位

网站不是一次性作品展示页，也不是必须持续写作的博客，而是一个可以长期更新的个人工作档案（Working Archive）。

它需要同时服务于：

- 让第一次访问的人快速理解我是谁、做过什么、现在在做什么；
- 展示真实项目、作品、实验和持续维护中的系统；
- 让面试官、潜在合作伙伴和普通访客看到具体产物与工作方式；
- 在未来新增内容时，尽量复用既有页面模板和视觉规则。

## 2. 第一版核心入口

### `/` — Home / Working Archive

首页负责快速建立理解，不承担全部内容细节。

主要模块：

- 简短的个人定位；
- Current Focus；
- 精选项目或最近更新；
- Working Archive 入口；
- 可选的 Currently Reading；
- Contact 入口。

### `/archive` — Projects / Archive

统一展示可公开的项目、作品、实验和研究系统。

每个条目至少标记：

- 类型；
- 状态：进行中、已完成、暂停或归档；
- 最近更新时间；
- 详情页入口。

这里不要求把所有项目都做成完整案例。重要项目进入详情页，次要项目可以只保留简短档案。

### `/archive/[slug]` — Archive Item Detail

作为项目、作品、实验和系统的通用详情模板。

建议包含：

- 项目背景与问题；
- 我的职责和关键判断；
- 实现或推进过程；
- 产物链接；
- Evidence / 验证信息；
- 当前状态；
- 后续计划或未解决问题。

Evidence 不等于单独的证据页面，也不等于必须放图片。它可以是在线地址、代码仓库、截图、文档、版本记录、测试结果和验收说明等可核验材料。

### `/now` — 当前阶段

Now 不是 Projects 页的“进行中筛选器”，而是回答：

> 如果一个一年没见的朋友问我最近在做什么，我会如何概括现在的生活、学习、工作和注意力？

建议包含：

- 最后更新时间；
- 当前所处阶段；
- 目前最重要的 2～4 个重点；
- 为什么现在关注这些事情；
- 当前暂时不做什么；
- 当前开放的交流或合作方向；
- 指向相关项目的链接。

第一版可以保持简短，不需要每日更新。建议在阶段发生变化时，或每季度更新一次。

### `/about` — About（暂不强制独立实现）

About 和 Home 的职责不同：Home 负责快速建立第一印象，About 负责补充个人背景、经历、长期兴趣和工作方式。

但如果第一版内容还不够丰富，About 可以先作为 Home 中的一个区块，暂时不出现在主导航。它是预留页面，不是第一版必须独立实现的页面。

### Contact

第一版作为 Home、Now、About 和页脚中的区块实现，不急于单独建立 `/contact`。

## 3. 当前页面关系

```text
Home
├── Archive
│   └── Archive Item Detail
├── Now
├── About（可先作为 Home 区块）
└── Contact（可先作为区块）
```

详情页应提供返回列表的路径；内容数量增加后，可以补充上一个、下一个和相关条目链接。

## 4. 目前不独立成页的内容

- Current Focus：先放在 Home 和 Now；
- Currently Reading：先作为 Home / Now 的小模块；
- 时间线：先作为 About 的模块；
- How I Work：先作为 About 或项目详情页的模块；
- Evidence：作为项目详情页中的验证区域；
- 联系方式：先作为共享区块。

## 5. 阅读内容策略

每天读书不等于必须马上建立一个书单页。

当前先把阅读作为一种内容类型保留：

- Home / Now 展示当前正在读的 3～5 本书；
- 每本书至少记录“为什么读”和“它与当前问题的关系”；
- 当形成一批有个人判断的记录后，再建立 `/reading` 或 `/library`。

不要只展示书名列表；阅读页面的价值应当是展示我正在通过什么内容形成判断、推进项目或调整方向。

## 6. 后续可新增页面

### 优先级较高

- `/reading` 或 `/library`：形成稳定阅读记录后使用；
- `/notes`：开始持续写作或整理短笔记后使用；
- `/updates`：需要记录项目进展时使用；
- `/resume`：需要面向面试官提供简历和经历时使用；
- `/lab`：实验性项目数量较多后使用。

### 内容积累后再考虑

- `/uses`：工具、工作环境和 AI 协作方式；
- `/timeline`：独立的经历时间线；
- `/collections`：书籍、网站、资料和主题收藏；
- `/tags`：内容数量较大后使用；
- `/search`：内容数量较大后使用；
- `/rss`：有稳定更新流后使用。

### 暂不建议第一版加入

- 实时状态 Dashboard；
- 健身或生活数据面板；
- 复杂的 RSS 聚合；
- 命令面板；
- 过度复杂的社交或互动功能。

## 7. 第一条实现链路

第一轮不要求一次性完成所有页面，先验证：

```text
共享 Header / 导航
→ Home / Working Archive
→ Archive 列表
→ 一个真实的 Archive Item Detail
```

这条链路需要回答：新增一个项目时，是否主要只需要补充内容，而不需要重新设计一套 UI。
