# Component / Design Dimension Inventory v0.1

状态：候选清单

更新时间：2026-09-14

## 1. 这份清单的作用

这不是最终的代码组件清单，也不是要求一次性完成 60 个设计实验的任务单。

它记录目前可能影响整个个人网站视觉、结构、内容呈现和交互体验的候选设计维度，作为后续 Lab 的候选池。

工作方式：

1. 先维护一份约 50～60 项的全站候选清单；
2. 根据真实页面内容和当前不确定性，选出第一轮约 12～18 项；
3. 对进入第一轮 Lab 的项目制作约 5 个可比较的样式；
4. 用户选择、评论、淘汰或要求融合；
5. 将已确认的结果回写到 Design Baseline 和实现计划。

这里的“组件”是设计层面的组件或设计维度，不一定对应一个 Astro 文件。一个候选项可能是基础规则、页面模式、内容模块、状态或交互行为。

## 2. 当前范围

清单覆盖：

- 全站视觉基础；
- 共享 Shell、导航和页面结构；
- Archive 列表；
- 项目详情页；
- Home、Now、About 的核心模块；
- 未来可能出现的 Notes、Reading、Resume、Lab 等页面模式；
- 暂时不进入第一轮实现的功能和状态。

当前页面内容仍是 v0.1，不要求在本清单阶段确定所有最终文案、所有项目和所有未来页面。

## 3. 状态与变体规则

| 状态 | 含义 | 默认处理 |
|---|---|---|
| 第一轮 Lab 优先 | 对视觉影响大、复用率高或当前不确定性高 | 优先挑选；通常制作 5 个变体 |
| 候选 | 可能需要设计，但可以等第一轮结果或真实页面验证 | 暂不制作完整 Lab；必要时制作 2～3 个变体 |
| 后续页面 | 依赖未来内容或未来页面 | 只记录，不进入当前 Lab |
| 暂不处理 | 当前目标之外，或会显著扩大范围 | 保留记录，不进入第一版 |

“第一轮 Lab 优先”不是最终入选结果；最终仍需要结合真实内容、实现成本和用户反馈确认。

## 5. 第一轮 Lab 的筛选原则

从上面 60 项中，第一轮优先选择：

- 会在多个页面复用的项目；
- 对 Working Archive 视觉识别影响大的项目；
- 用户目前存在明显审美犹豫的项目；
- 可以用真实项目和真实内容验证的项目；
- 不依赖尚未确定的未来页面。

初步候选包括：

- F-01、F-02、F-03、F-04、F-06、F-07、F-09；
- S-01、S-04、S-06；
- A-01、A-03、A-05、A-06、A-07；
- D-01、D-02、D-08；
- P-01、P-02、P-04。

这份初步候选超过最终第一轮的数量上限，下一步还需要根据真实内容和实现依赖再压缩到约 12～18 项。

## 6. 后续工作边界

本清单暂不包含：

- 每个组件的最终颜色值；
- 最终 CSS 或 Astro 代码；
- 所有页面的完整文案；
- 所有未来功能的详细交互；
- 已经确认的最终视觉方案。

这些内容应在对应的 Lab、Baseline 或实际实现阶段记录。
