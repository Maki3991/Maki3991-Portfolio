# Page Implementation Workflow v0.1

更新时间：2026-09-16

## 目的

这份文档记录个人网站进入页面实现阶段后的统一工作流，避免 Agent 在没有完成分析和确认前直接写代码，也避免每轮产生大量互相重复的 Markdown。

当前工作流的最小单位是：

> 一个页面或一个明确的大板块 → 一份实施审计 → 用户确认 → 一次实现 → 浏览器验收。

## 设计依据的层级

页面实现时不需要重新阅读所有研究文档，只按以下顺序读取：

1. 网站目标和已确认的内容/信息架构；
2. Design Baseline v0.2：全站视觉原则；
3. Component Contract v0.1：组件的结构、样式和行为边界；
4. 当前页面对应的参考网站、Lab 样例和代码；
5. 当前旧页面及其内容审计；
6. 本页面自己的实施审计文档。

其中，旧网站代码只是待审计对象，不是新版视觉标准。Lab 代码是参考样例，不是无需判断就必须复制的代码。

## 全局阶段

### 1. 目标与约束

明确网站要传达的身份、长期目标、受众和明确拒绝的视觉风格。

完成状态：网站目标和主要设计禁区已经确定。

### 2. 参考网站与设计基线

整理外部参考，提炼 Working Archive 等方向，形成可执行的 Baseline。

完成状态：有全站视觉原则，而不是只有几个网站链接。

### 3. 组件 Lab 与 Component Contract

为高影响组件选择具体样式，并记录间距、边框、字体、动效、状态和响应式规则。

完成状态：新 Agent 可以根据 Contract 创作同一套 UI，而不是重新猜风格。

### 4. 网站结构与内容决策

确定 Home、Archive、Now、About、Contact 等页面的职责、关系和首批内容。

完成状态：知道每个页面解决什么问题，但不要求现在写完所有最终文案。

### 5. 旧站审计与内容迁移

识别旧站中应该保留、改写、匿名化、隐藏或暂不公开的内容，并建立 Archive 数据记录。

完成状态：内容来源、公开边界和证据状态清楚。

### 6. 页面实施循环

逐个页面执行下面的页面级闭环。当前项目正式处于这一阶段。

### 7. 跨页面验收

所有主要页面完成后，统一检查导航、链接、响应式、可访问性、内容一致性、构建和部署。

完成状态：网站作为整体通过验收，而不是每个页面各自能运行。

## 页面级循环

### A. 选定本轮范围

一次只选择一个页面或一个大板块，并明确本轮不处理的内容。

当前建议顺序：

1. Home；
2. Archive；
3. Now；
4. About；
5. Contact；
6. 全站整合。

Archive 已经存在技术原型，但仍需重新经过本循环，不能把原型直接视为最终方案。

### B. 实施前审计：不写代码

创建一份页面文档，例如：

```text
home-page-implementation-audit-v0.1.md
```

这份文档只需要包含以下五部分：

#### 1. 扫描当前页面

记录当前页面的：

- 页面结构和滚动顺序；
- 当前文字和内容来源；
- 现有组件和交互；
- 桌面端/移动端表现；
- 明确的问题和不应继承的旧风格。

#### 2. 重新读取设计库

对照 Design Baseline 和 Component Contract，说明本页面要遵循哪些全站规则，以及哪些规则在本页面不适用。

#### 3. 映射参考方案和代码样例

对每个主要区域写清楚：

- 使用哪个已选组件；
- 参考哪个 Lab 样例；
- 保留什么；
- 哪些地方只借鉴结构，不复制视觉；
- 是否需要新的组件变体。

#### 4. 定位修改位置

写明需要修改的：

- 页面文件；
- 共享组件；
- 样式文件；
- 内容文件；
- 图片或数据文件；
- 路由和链接。

#### 5. 列出待确认问题

所有影响内容、结构、视觉或交互的问题都必须在这里停下来询问用户。

### C. 用户确认关卡

AI 不能自行替用户决定以下问题：

- 页面最终区域顺序；
- 个人身份和文案语气；
- 哪些内容公开；
- 是否加入某个交互或动效；
- 参考方案之间如何取舍；
- 旧站内容是否保留。

用户确认后，实施审计文档进入 `confirmed` 状态，才允许写代码。

### D. 实现

只实现已经确认的范围。实现阶段不顺便：

- 增加新的全局视觉方向；
- 修改尚未确认的其他页面；
- 添加新的组件 Lab；
- 自行扩展页面内容；
- 把技术方便误认为设计正确。

### E. 验收

每次实现后至少检查：

- 桌面端截图；
- 移动端截图；
- 是否有横向溢出；
- 所有按钮和链接是否可用；
- hover/focus/展开等已实现交互；
- 浏览器控制台错误；
- `npm.cmd run build`；
- 内容是否符合已确认的真实信息和公开边界。

验收结果写回同一份页面实施审计文档，不为每一个检查项额外创建 Markdown。

### F. 用户最终接受

用户可以选择：

- 接受：页面进入 `accepted`；
- 局部修改：回到实施阶段，只处理指定差异；
- 方向不满意：回到实施前审计，重新讨论方案；
- 内容未准备好：保留结构，标记为 `content-pending`。

## 与王振宇五步的关系

王振宇的五步正好对应实施前审计的五个部分：

1. 扫描当前页面；
2. 重新读取设计库；
3. 查看参考方案和代码样例；
4. 定位具体修改位置；
5. 列出不确定项并与人确认。

区别是：这五步不是整个网站项目的全部流程，而是每个页面正式写代码前必须经过的关卡。

## 双方职责

### Agent

- 读取并整理当前有效资料；
- 扫描现有页面；
- 提出页面方案和具体选项；
- 明确不确定项和风险；
- 在确认后实现；
- 运行构建、浏览器和响应式验收；
- 记录实际结果和遗留问题。

### 用户

- 决定身份、内容、公开边界和审美取舍；
- 确认或否决页面方案；
- 判断实际视觉是否符合预期；
- 接受、要求局部修改或退回方案。

## 当前项目状态

| 对象 | 状态 |
| --- | --- |
| 全站设计方向 | 已确定：Light-first Working Archive，Dark mode 后续实现 |
| Component Contract | 已完成初版 |
| 网站结构与首批内容 | 基本确定 |
| Archive 数据和技术原型 | 已有，但尚未完成页面级设计确认 |
| Home 页面实施审计 | 下一项正式工作 |

## 当前禁止事项

在 Home 页面实施审计获得确认前，暂不：

- 继续扩展 Archive 功能；
- 创建 Archive 详情页；
- 修改全站 Header 作为顺手优化；
- 开始暗色模式；
- 再次增加组件数量；
- 同时实现多个页面。

## 完成定义

一个页面只有同时满足以下条件，才算本轮完成：

1. 实施审计文档已确认；
2. 代码实现已完成；
3. 桌面端和移动端已检查；
4. 构建通过；
5. 关键交互已检查；
6. 内容和公开边界没有越过用户决定；
7. 用户接受最终结果；
8. 遗留问题已记录。
