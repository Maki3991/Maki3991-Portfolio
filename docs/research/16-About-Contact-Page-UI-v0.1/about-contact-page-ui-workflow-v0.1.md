# About / Contact Page UI 工作流 v0.1

状态：当前有效

更新时间：2026-09-20

## 1. 任务边界

本轮只处理 About 和 Contact 两个页面。它们是旧网站遗留页面，需要在当前 Foundation、Component Contract 和已验收的 Home / Archive / Now 视觉基线上重新组织。

### 已冻结的参考基线

- Home、Archive、Now 的整体视觉方向不在本轮重新发散。
- Foundation token 继续作为生产来源：颜色、字体、字号、字重、行高、间距、圆角、边框、阴影和响应式断点优先复用已有 token。
- About / Contact Hero 右侧不新增统计或文字栏。
- About / Contact Hero 底部暂不增加分割线；两页保留开放留白。
- 用户不需要阅读或审查实现代码，只在真实视觉结果、内容事实或页面行为需要判断时参与。

### 本轮不处理

- 不重新设计全站 Foundation。
- 不修改 Home、Archive、Now 的生产样式，除非发现明确的跨页面回归。
- 不因为 About / Contact 的旧代码而恢复旧版暖色、卡片墙或旧字体风格。
- 不在内容尚未确定时用占位文案填满页面。

## 2. 工作阶段

### 阶段 0：冻结基线

确认当前稳定页面、当前已接受的设计系统和本轮范围。任何共享样式改动都必须说明会影响哪些已稳定页面。

产出：范围说明和不改动清单。

### 阶段 1：只读审计

Agent 读取并记录：

- Astro 页面结构和真实文案；
- `secondary-pages.css`、`global.css`、`display-title.css` 的作用范围；
- `src/data/` 与 `src/site-content/settings/` 的事实来源；
- 图片、二维码、PDF 和外部链接资源；
- 现有交互脚本、键盘行为、响应式规则和潜在溢出；
- 页面与共享组件的影响范围。

产出：保留 / 重写 / 删除清单，以及 P0 / P1 问题列表。此阶段不修改生产代码。

### 阶段 2：内容结构契约

先确定页面要表达什么，再决定区块长什么样。

About 需要确定：

- 正文保留几个主题；
- “我是谁”“我如何工作”“我关心什么”“我正在寻找什么”的关系；
- 哪些内容应留在 About，哪些事实应回到 Archive 或 Now。

Contact 需要确定：

- 邮箱、微信和公开账号的优先级；
- 联系入口是否分组；
- 二维码是主要入口、辅助入口，还是仅保留在列表中；
- 联系提示是否需要说明项目背景和下一步。

产出：内容结构决定。事实、链接和公开边界由用户确认；Agent 不替用户编造经历或联系方式规则。

### 阶段 3：最小 Review Preview

Foundation 已经完成，本轮不再为每个 CSS 参数制作完整 Lab。只对确实影响判断的变量提供可视化选择：

About：

- 四段开放列表 / 连续叙事 / 保留五段旧结构；
- 正文密度与区块节奏；
- 是否使用编号、细线或其他结构提示。

Contact：

- 联系入口分组方式；
- QR 卡片与链接列表的关系；
- 桌面端双栏和移动端单栏的内容顺序；
- 链接列表的密度和辅助说明位置。

预览只保留视觉要素名称、方案选项、必要的交互和反馈入口，删除无关装饰。用户只需看结果并选择或自由描述修改意见。

### 阶段 4：生产实现

在没有重大未决选择时，Agent 直接修改生产代码，不要求用户审查代码。

优先文件：

- `src/pages/about.astro`
- `src/pages/contact.astro`
- `src/styles/secondary-pages.css`

只有在审计证明共享规则确实是问题时，才修改：

- `src/styles/global.css`
- `src/components/`
- `src/data/site.ts`
- `src/site-content/settings/`

每次只处理一个明确切片：先 Page Shell / Hero，再 About 正文，再 Contact 入口和二维码交互。

### 阶段 5：局部验收

每个切片完成后检查：

- 桌面端视觉层级、间距和内容宽度；
- 390 × 844 左右的移动端布局；
- 中文、英文、数字混排和长文本；
- Hover、Focus、Click、关闭和键盘行为；
- 横向溢出、控制台错误和资源加载；
- `npm.cmd run build`。

只有受影响页面通过后，才进入下一个切片。

### 阶段 6：跨页面回归

About / Contact 完成后，再统一查看 Home、Archive、Now、About、Contact：

- Header 和导航当前态；
- 页面标题顶部节奏；
- Footer 顶部线和底部留白；
- Foundation token 是否被局部样式绕开；
- 桌面端、移动端和键盘路径；
- 生产构建和外链 / 资源。

组件通过不等于网站完成；跨页面、内容、响应式、可访问性和部署仍是独立闸门。

### 阶段 7：沉淀与关闭

验收通过后回写：

- Component Contract 中的页面级组合规则；
- 本目录的决定和审计状态；
- `docs/research/README.md` 的当前入口；
- 必要的截图或运行证据路径。

## 3. 决策边界

Agent 可以直接决定：

- CSS 选择器、文件拆分和 Astro 实现方式；
- 已有 token 的复用；
- 可由代码和现有证据确定的响应式、可访问性和构建修复；
- 明显属于旧版遗留、且与当前基线冲突的实现删除。

只有以下问题需要交给 Maki：

- 真实经历、公开范围和链接事实；
- 页面正文的取舍和表达重点；
- 两个都会明显改变视觉结果的布局方案；
- 联系入口的优先级和行为；
- 最终视觉反馈与是否接受。
