## 一、每轮必须遵守的规则

### 1. 一轮只审计一个组件

Agent 每次只能从“待审计”队列中取一个组件。

允许读取它影响的共享文件和相邻组件，用于确认影响范围；不允许顺手审计或修改下一个组件。

### 2. 审计阶段不改生产代码

审计只完成第 1–4 步，并输出第 5 步问题：

1. 扫描当前组件实现；
2. 重新读取设计库；
3. 查看已选方案、Lab 代码和必要参考；
4. 找出准确修改位置和影响范围；
5. 列出所有需要 Maki 判断的问题，然后停止。

没有用户确认，不得修改 `src/`、不得重写文案、不得顺手调整相邻组件。

### 3. 用户确认后才实现

用户回答第 5 步后，Agent 只实现当前组件及明确依赖，然后完成：

- 桌面端截图；
- `390 × 844` 左右的移动端截图；
- Hover / Focus / Click / 键盘行为（若适用）；
- 横向溢出检查；
- 控制台检查；
- `npm.cmd run build`；
- 真实内容、长标题和中英文混排检查。

验收通过后，才把当前组件标记为“已实现 / 已验收”，再进入下一个组件。

## 二、状态定义

| 状态              | 含义                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| `已审计`          | 第 1–5 步已经完成，用户已经做出当前选择；不需要重复审计。                 |
| `待审计`          | 还没有执行本组件的第 1–4 步。                                             |
| `待用户确认`      | 第 1–4 步完成，正在等待第 5 步回答。                                      |
| `待实现`          | 用户已经确认，但代码还没有修改。                                          |
| `待验收`          | 代码已经修改，但尚未完成截图、构建和用户视觉确认。                        |
| `已实现 / 已验收` | 代码、浏览器行为、移动端和构建均已通过。                                  |
| `暂缓`            | 依赖未来页面、内容或暗色主题，当前不进入队列。                            |
| `重新评估`        | 真实内容证明原选择不合适，只重新打开当前组件的 Lab 方案，不推翻全站方向。 |

## 七、完成一个组件后的回写

完成实现和验收后，Agent 必须更新：

1. 本队列中该组件的状态；
2. Component Contract 中的生产代码入口、截图和验收状态；
3. 必要时更新当前批次记录；
4. 明确下一项待审计组件。

不要静默删除旧决定。若视觉选择被真实内容证明不合适，保留旧版本并创建新的 Contract 版本。
