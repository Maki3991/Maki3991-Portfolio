# 深度核验：依赖、许可证与采用建议

> 核验日期：2026-09-12
>
> 这份文件补充第一轮候选研究。它记录公开仓库与官方文档中能够直接核验的技术事实，不等同于在本地克隆并成功构建这些项目。

## 结论先行

当前最适合继续深挖的方向不是直接选择一个完整模板，而是拆成三层：

1. **内容与路由骨架**：优先参考 SDBurt 与 Astro Kami。
2. **长期内容模型**：参考 Astro Content Collections、SDBurt 的 blog/projects/work 分层，以及 Astro Kami 的 post/page/showcase 分层。
3. **交互组件**：只在确实需要时，从 Starwind UI 这样的 source-first 组件库挑选单个组件；不把整个组件库当成网站视觉风格。

Kepler 更适合研究“一个设计系统如何覆盖博客、作品集和落地页”，但它的 navy × orange、硬偏移阴影和 marketing preset 不应直接成为本项目的视觉方向。hmbldv 更适合研究项目版本、提交记录、Wiki 与文档式详情页，不宜在没有实际需求时整体照搬。

## 逐项核验

### Astro Kami

- 仓库：[automann/astro-kami](https://github.com/automann/astro-kami)
- 官方演示：[astro-kami](https://automann.github.io/astro-kami/)
- 许可证：仓库 README 标明 MIT。
- 可核验技术事实：Astro 7 静态输出；post/page 内容集合；英文与简体中文路由；MD/MDX；RSS、sitemap、OG 图片、Pagefind、可选 Giscus、可选分析和 webmentions；无客户端框架运行时。
- 内容入口：`src/site.config.ts`、`src/content/post/`、`src/content/page/`、`src/data/showcase.ts`。README 明确说明站点个性化集中在配置、内容集合和 showcase 数据中。
- 构建入口：`pnpm check`、`pnpm build`、`pnpm test`，生产输出为静态 `dist/`。
- 采用判断：适合借鉴“内容优先、配置集中、文章和项目并存”的结构；不建议直接继承它的编辑型字体、国际化和 OG 图片全套功能，除非这些能力确实进入需求。
- 风险：功能面较宽，包含字体、代码高亮、数学公式、OG 图片生成、Pagefind、评论、分析和 webmentions；整体迁移会带来超出个人网站首版的维护面。

### Kepler

- 仓库：[kpab/astro-kepler](https://github.com/kpab/astro-kepler)
- 官方演示：[astro-kepler.pages.dev](https://astro-kepler.pages.dev/)
- 许可证：`package.json` 标明 MIT。
- 可核验技术事实：Astro 7、Tailwind CSS 4、TypeScript、MDX、Pagefind；博客和作品集使用内容集合；作品集支持可过滤项目网格和 case study；默认零客户端框架运行时；构建命令会先执行 `astro build` 再生成 Pagefind 索引。
- 环境约束：`package.json` 标明 `pnpm@9.14.4`，Node.js `>=22.12.0`。
- 内容入口：`src/site.config.ts`、`src/content/blog/`、`src/content/work/`；README 还明确给出 blog/work 的 schema 和页面结构。
- 采用判断：适合借鉴“同一套 token、组件和内容模型覆盖多个页面模式”，以及搜索、筛选、文章、案例研究的关系。
- 风险：默认风格强、预设多，容易把个人网站带向产品落地页；搜索在 build/preview 阶段才完整工作；Node 版本和 Tailwind 版本都比当前项目更激进。

### SDBurt Astro Portfolio

- 仓库：[SDBurt/astro-portfolio](https://github.com/SDBurt/astro-portfolio)
- 实站：[sdburt.com](https://sdburt.com/)
- 许可证：README 标明 MIT。
- 可核验技术事实：Astro 7、TypeScript、无客户端框架运行时、MDX、Shiki、vanilla CSS、自定义 CSS 变量、内容集合、自动目录、view transitions、键盘导航和 reduced-motion 支持。
- 内容入口：README 给出 `src/content/blog/`、`src/content/projects/`、`src/content/work/` 三类内容，以及可复用组件、布局、页面、样式、配置等目录。
- 设计系统：README 明确写出语义色彩 Token、4px 间距、rem 字体尺度和语义组件类；这是当前“新增板块不重做 UI”目标的直接参考。
- 构建与部署：要求 Node.js `22.12+`，使用 pnpm；`pnpm build` 生成静态站点，部署说明以 Cloudflare Workers Static Assets 为例。
- 采用判断：目前最接近本项目“长期更新、项目与文章并存、静态 Astro、设计系统可维护”的结构参考。
- 风险：仓库当前技术版本是 Astro 7/Node 22.12+，不能把它的版本要求直接套入当前项目；还需要本地安装与构建验证。

### hmbldv Portfolio Template

- 仓库：[hmbldv/portfolio-template](https://github.com/hmbldv/portfolio-template)
- 许可证：README 的 License 部分标明 MIT。
- 可核验技术事实：Astro 5.16、TypeScript、CSS Grid、MDX、内容集合；项目、博客、Wiki、证书；项目版本历史、提交记录 changelog、sticky TOC、Mermaid、面包屑。
- 内容入口：`src/content/blog/`、`src/content/projects/`、`src/content/wiki/`，另有 `src/data/certifications.ts`。
- 采用判断：最值得借鉴的是把“项目”视为持续变化的记录：项目版本、提交历史、当前版本与旧版本之间的关系，适合长期维护的个人档案。
- 风险：目前公开资料中未找到可直接核验的在线演示；README 中的 Lighthouse 数字属于作者自述，不能作为本次研究的实测结果；Mermaid 使用客户端渲染，会增加页面行为和验证成本。

### Starwind UI

- 官方文档：[Starwind UI](https://starwind.dev/docs/getting-started/)
- 组件目录：[Components](https://starwind.dev/docs/components/)
- 仓库：[starwind-ui/starwind-ui](https://github.com/starwind-ui/starwind-ui)
- 许可证：仓库 LICENSE 和 README 均标明 MIT。
- 可核验技术事实：面向 Astro、React 和 Vue 的 55 个可移植组件；组件以源代码形式加入项目；由共享、框架中立的 Runtime 提供行为；文档包含表单、导航、弹层、反馈、布局、内容和媒体等分类。
- 采用判断：适合在已有视觉 Token 之后补充 Dialog、Popover、Tabs、Accordion、Menu 等有交互和无障碍要求的组件；不适合用来决定网站的颜色、字体和整体布局。
- 风险：仓库本身是多框架 monorepo，完整采用会引入不必要的理解面；“accessible”是设计目标和文档声明，项目仍需在本地对具体组件进行键盘、焦点和 reduced-motion 测试。

### Ronald Lopez 的设计系统案例

- 案例：[Ronald Lopez Portfolio Case Study](https://www.ronglopez.com/projects/ronglopez-portfolio.html)
- 定位：不是可直接安装的模板，而是一个“研究 → 原则 → 系统 → 页面”的设计过程案例。
- 可借鉴内容：语义色彩角色、4px 间距、对比度、键盘和 reduced-motion、Storybook、组件和页面模式之间的关系。
- 采用判断：用于指导本项目如何把“我不喜欢 AI 味”转化为可检查的 Token 和组件规则，而不是复制其具体配色或页面样式。

## 采用优先级

| 优先级 | 参考对象 | 只提取什么 | 暂不提取什么 |
|---|---|---|---|
| 1 | SDBurt | 内容集合分层、语义 Token、项目/文章/经历并存、静态站结构 | Astro 7/Node 22 的版本升级、Cloudflare 专属配置 |
| 2 | Astro Kami | 内容优先、配置集中、文章详情能力、项目 Showcase | 国际化、OG 图片生成、评论和 webmentions 全套 |
| 3 | Ronald | 设计 Token、组件契约、无障碍和动效验收方法 | 具体颜色、字体和视觉风格 |
| 4 | hmbldv | 项目版本、提交 changelog、Wiki、文档式详情页 | Mermaid 与完整文档站模式 |
| 5 | Starwind UI | 需要时挑选的交互组件实现 | 整套视觉系统和多框架工程 |
| 6 | Kepler | 多页面模式共享 token、搜索和筛选的组织方法 | 默认 navy/orange 视觉、营销页 preset |

## 当前仍未证明的事项

以下事项不能由公开 README 或线上页面直接证明，需要本地独立验证：

- 在当前 Windows 环境中逐个安装依赖并成功执行 build。
- 当前项目 Astro 版本与 Astro 7 模板之间的迁移成本。
- 每个候选的完整键盘焦点顺序、屏幕阅读器语义和 reduced-motion 行为。
- 许可证是否覆盖所有字体、图标、图片和第三方插件，而不只是仓库主许可证。
- hmbldv 模板的真实页面交互，因为目前只有仓库资料可核验。
- 这些候选对中国大陆网络环境和未来部署方案的实际访问稳定性。

## 给下一阶段的明确动作

下一阶段不再扩大候选池，先从 SDBurt、Astro Kami、hmbldv 中选 2 个做本地浅克隆检查，再单独验证 Starwind 的 2 个交互组件。输出应包括：安装命令、Node/pnpm 要求、build 结果、依赖数量、许可证检查、页面截图和“可复用/应重写/不采用”三栏结论。
